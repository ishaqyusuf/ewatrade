# Storefront component SDK

The local factory is complete through TF10. This package contains the bounded SDK,
isolated build, [artifact pipeline](PIPELINE.md) and safe `./operations` summaries.
Reviewed static promotion lives in `../storefront-templates/src/generated/`;
registration and local qualification remain separate from deployment.

TF09-01 provides a presentation contract and local isolated qualification build. It does not generate components, register templates, publish artifacts or execute generated code in the production application. A generated component still requires source review and an ordinary reviewed code release before runtime inclusion.

`./contracts` projects bounded public data with `createComponentInput`. A manifest owns one section, finite editable settings, public business/catalog/service resources, action intents, asset IDs and declared CSS tokens. Database models, tenant scope, credentials, provider clients and arbitrary network access are absent. Catalog arrays are capped at 50, nested options at 20, assets at 32, actions at 50 and serialized input at 256 KiB. The projection recursively freezes public arrays and records. Asset URLs come from the trusted caller's approved asset map, never generated settings. The caller must supply only URLs already approved by the existing public asset policy.

Generated TSX imports only named React presentation types/Fragment and `./sdk` primitives. `ComponentProps` contains public presentation input; it has no callback. `ComponentFrame` and `ComponentAsset` read the trusted private host context, so a generated object cannot replace theme or asset authority. `ComponentAction` renders an approved action index without an event callback. The separate trusted `./host` adapter handles trusted user clicks and dispatches only an action from its own input. The existing server action adapter must recheck current permissions, scope and preview mode before any business effect. Generated imports cannot access `./host`, internal context, the isolation runner or provider modules.

The default export contains only pure contracts. `./source-policy` uses TypeScript 5.9.3 AST diagnostics and a small scoped CSS grammar to reject unsupported imports, execution constructs, direct JSX raw HTML/URL surfaces, handlers and undeclared tokens. These diagnostics are qualification rules, not a JavaScript security sandbox or proof of safe rendered output. For example, a constructed React element object can evade direct JSX checks. `./isolation` is an explicit Node-only build entry; no fs/process/Docker exports enter the client SDK.

Run focused local checks from the repository root:

```sh
bun --env-file=/dev/null test packages/storefront-components/src
./node_modules/.bin/tsc -p packages/storefront-components/tsconfig.json --noEmit --incremental false
bun --env-file=/dev/null packages/storefront-components/scripts/check-isolation.ts
```

The last command requires an already running local Docker daemon and the exact cached image. It never starts a daemon, pulls an image or installs dependencies. Context configuration is read before any daemon access; non-local/TLS Docker endpoints are refused. The compiler is Bun **1.3.14** in `oven/bun@sha256:e10577f0db68676a7024391c6e5cb4b879ebd17188ab750cf10024a6d700e5c4` (image ID `sha256:b4e28676860761b02257849f827ecee18611343a0541b1bf45007dc59be0bcfb`). The repository's Bun 1.3.9 launches the host checks; it is not the compiler pin. The explicit check script avoids Bun 1.3.9's observed test-harness empty child-process stdout issue.

Only content-hashed React 19.1.0, React DOM 19.1.0, scheduler 0.26.0 and the three trusted SDK runtime files enter a new secret-free workspace. The exact dependency tree hashes are exported as `COMPONENT_DEPENDENCY_HASHES`. Host environment files, repository config, plugin config and package install scripts are excluded. Nested symlinks and non-regular dependency files are refused. Optional fixtures must be immutable objects returned by `createComponentInput` for the exact manifest, verified by an in-process weak reference fence.

The normal `bun build` runs once in one container; SSR executes its captured bundle against one to three trusted fixtures in a second container. Pass one `ComponentInput` or a readonly array to `runIsolatedComponentBuild`. The original `html`, `inputHash` and `htmlHash` describe the first fixture; `htmlFixtures`, `fixtureInputHashes` and `fixtureHtmlHashes` preserve the complete ordered qualification. Fixtures enter the workspace only after compilation. Generated code is never imported by the host. Both containers use `--pull=never`, network none, a read-only root, non-root UID 65534, no capabilities, no privilege escalation, no devices or host sockets, a single read-only source mount, 512 MiB memory/swap, one CPU and 64 PIDs. Each execution has a 20 second wall limit and a 1 MiB combined output limit across all fixtures; setup/inspect/cleanup Docker calls each have a 15 second timeout. Writable tmpfs is limited to 64 MiB temporary space and 8 MiB output, with no executable permission. Bundle output is capped at 512 KiB and each fixture's SSR HTML at 256 KiB. Subprocesses remain subject to these same container limits.

Before compilation and SSR, the trusted driver verifies a credential-free environment, denied reads of an unmounted host canary, denied source/root writes, a functioning internal loopback control, no external interface or route and a refused external connection. The host independently inspects image, network, memory, user, mount and privilege settings. Missing Docker, pins, probes, limits, cleanup or malformed output fails closed. Owned containers are removed in `finally`; the private workspace is removed after the result is captured. A cleanup failure is reported, never hidden behind a successful build.

The result contains the qualification bundle, fixture SSR HTML and independently computed source/CSS/manifest/input/dependency/SDK/build-recipe/output hashes with guard evidence. Returned SSR HTML is untrusted inert data: it must not be inserted into a browser DOM or trusted page. Sandboxed review with restrictive CSP and output validation belongs to TF09-02 before any preview. The bundle exports the trusted SSR qualification entry with its component; it is **not** a production renderer export. Artifact provenance uses the separate `storefront-component-artifact` contract, with model/request provenance distinct from `SiteDesignRun`. Acceptance, generation jobs, durable storage, reviewed artifact promotion and template registration belong to later tickets.
